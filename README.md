# NEEDIT | Frontend

**대학생의 실제 불편함을 AI로 구체화하고, 개발 프로젝트와 서비스 출시까지 연결하는 플랫폼**

NEEDIT은 NEED와 IT를 결합한 이름으로, 학생에게 필요한 것을 IT 기술로 해결한다는 의미입니다. 학생은 학교생활의 불편함을 제보하고 공감하며, 개발자는 이를 바탕으로 프로젝트를 시작하고 완성한 서비스를 공유할 수 있습니다.

2026 경북대학교 컴퓨터학부 해커톤 프로젝트의 프론트엔드 저장소입니다.

- 서비스: [NEEDIT](https://needit-frontend.onrender.com)
- 프론트엔드: [needit-frontend](https://github.com/j8nyun9/needit-frontend)
- 백엔드: [needit-backend](https://github.com/j8nyun9/needit-backend)

## 서비스 흐름

**불편함 제보 → 공감으로 수요 확인 → AI 기획안 생성 → 불편함 채택 및 프로젝트 개발 → 서비스 공개 → 사용자 피드백**

단순히 AI로 아이디어를 생성하는 데 그치지 않고, 실제 학생의 문제에서 출발해 개발과 사용자 검증까지 연결합니다.

## 주요 기능

| 화면 | 구현 기능 |
| --- | --- |

| 불편함 탐색 | 검색, 카테고리·최신순·인기순·My 필터, 내 AI 기획안 생성 여부 표시 |
| 불편함 상세 | 공감·취소, 댓글 등록, 본인 글·댓글 수정 및 삭제, 연결된 프로젝트 조회 |
| AI 기획안 | 해결 가능성 및 이유 분석, 서비스 소개·주요 기능·기술 스택·MVP 범위 제안, 결과 복사 |

| 프로젝트 상세 | 서비스 소개·사용 방법·주요 기능, 관련 불편함, 단계·예정일, 관심 등록, 서비스 링크 |
| 프로젝트 관리 | 본인 프로젝트 소개·단계·일정 수정, 서비스 공개·공개 취소, 프로젝트 삭제 |
| 후기·오류 제보 | 서비스 운영 중인 프로젝트에 의견 등록, 본인 의견 수정·삭제, 하트·취소 및 개수 표시 |
| 마이페이지 | 내가 등록한 불편함·공감한 불편함·관심 프로젝트·참여 프로젝트, 프로필, 최근 활동 |
| 출시 알림 | 관심 프로젝트 또는 공감한 불편함에 연결된 프로젝트의 출시 목록과 읽음 상태 |
| 서비스 소개 | README 콘셉트의 문서 화면과 스크롤 목차 |

### 이용 및 권한 기준

- 로그인 없이 불편함·프로젝트 등 공개 내용을 둘러볼 수 있습니다.
- 글 작성, 공감, 댓글, AI 생성, 프로젝트 채택, 관심 등록 및 후기 작성에는 로그인이 필요합니다.
- AI 기획안은 **생성한 사용자 본인에게만** 제공됩니다. 저장된 결과는 다시 조회할 수 있습니다.
- AI가 **소프트웨어만으로 해결하기 어려움**으로 판단하면 해결 가능성과 이유만 표시하고 채택을 막습니다.
- 다른 사용자는 같은 불편함에서 각자의 프로젝트를 만들 수 있으며, 동일 사용자의 중복 채택은 제한합니다.
- 프로젝트 상태는 **기획 중 / 개발 중 / 테스트 중 / 서비스 운영 중**입니다. 상세 진행 현황에서는 현재 단계만 색상으로 표시합니다.
- 마이페이지의 ‘참여 프로젝트’는 현재 구현에서 **본인이 담당자로 등록된 프로젝트**입니다.
- 불편함을 삭제해도 연결된 프로젝트는 유지됩니다. 프로젝트를 삭제해도 원본 불편함과 개인 AI 기획안은 유지됩니다.

## 로컬 실행

Node.js와 npm이 필요합니다. 개발·검증에는 Node.js 24를 사용했습니다.

```bash
git clone https://github.com/j8nyun9/needit-frontend.git
cd needit-frontend
npm ci
```

`.env.example`을 복사해 `.env.local`을 만들고, 필요한 설정만 입력합니다.

```dotenv
# 기본 개발 설정은 /api 요청을 배포된 백엔드로 프록시합니다.
# 로컬 백엔드와 연결하려면 다음 값을 설정합니다.
API_PROXY_TARGET=http://127.0.0.1:4000

# 선택: 프록시 대신 API 주소를 직접 지정할 때 사용합니다. /api를 포함합니다.
# VITE_API_BASE_URL=https://needit-backend-d3lv.onrender.com/api
```

```bash
npm run dev
```

개발 서버 기본 주소는 `http://127.0.0.1:5173`입니다. 포트가 사용 중이면 터미널에 표시된 주소를 확인합니다.

Supabase 서버 비밀 키와 Gemini API 키는 **백엔드에서만 설정**합니다. `VITE_` 환경변수에 비밀 키를 넣지 않습니다.

## 빌드 및 배포

```bash
npm run build
npm run preview
```

- 빌드 결과: `dist/`
- Render 서비스 유형: Static Site
- Build Command: `npm ci && npm run build`
- Publish Directory: `dist`
- 기본 프로덕션 API: `https://needit-backend-d3lv.onrender.com/api`
- 다른 백엔드를 사용할 경우 `VITE_API_BASE_URL`을 설정한 뒤 다시 빌드합니다.

프로필·글·반응·프로젝트 등 서비스 데이터는 백엔드 API에서 가져옵니다. 로그인 정보는 브라우저 탭의 `sessionStorage`에 보관하고, 현재 화면·필터·상세 탭은 URL 또는 브라우저 저장소로 복원합니다. 저장하지 않은 폼 입력 전체를 복구하는 기능은 아닙니다.

## 시연 순서

1. 서비스를 열고 불편함·프로젝트를 탐색합니다.
2. 준비된 Supabase Auth 계정으로 로그인합니다.
3. 불편함을 등록하고, 상세에서 AI 기획안을 생성합니다.
4. 채택 가능한 결과라면 ‘불편함 채택하기’를 누르고 완료 예정일을 선택해 등록합니다.
5. 내 프로젝트 상세에서 소개·단계·일정을 수정합니다.
6. ‘완성한 서비스 등록’에서 실제 배포 주소와 사용 방법을 입력해 공개합니다.
7. 다른 계정으로 서비스를 이용하고 후기·하트를 남깁니다.
8. 관심·공감 관계가 있는 계정에서 출시 알림과 마이페이지를 확인합니다.

시연 계정은 Supabase Authentication에 미리 생성해야 합니다. 계정 정보는 심사용 안내에 별도로 전달합니다.

## 폴더 구조

```text
src/
├── App.jsx                 # 화면 전환, 인증 상태, 공통 데이터

├── features/problems/      # 불편함 등록 화면

├── pages/                  # 탐색, 프로젝트, 마이페이지, 로그인, 소개

├── styles/                 # 공통·반응형 스타일
└── utils/                  # 화면 이동 기록, 기획안 문서 변환
```

## 검증 및 현재 범위

- `npm run build`로 프로덕션 빌드를 확인했습니다.
- 백엔드의 인증·작성자 권한·저장·프로젝트 채택 등은 백엔드 저장소의 테스트로 검증합니다.
- 서비스 공개는 **외부에서 배포한 서비스 URL을 등록하는 방식**입니다. NEEDIT이 개발자의 소스 코드를 호스팅하거나 자동 배포하지 않습니다.
- 출시 알림은 종 버튼을 열 때 조회하며, 이메일·브라우저 푸시 알림은 제공하지 않습니다.
- 실제 배포 환경에서는 Supabase 마이그레이션과 API 환경변수가 적용되어 있어야 합니다.
